# Data

This folder holds everything needed to recompute the numbers, tables and figures without the raw data. The raw results and logs (270 files, about 428 MB) are not in git. They are the GitHub Release asset `data-v1`, described in [RAW.md](RAW.md). The traces are published only as hashes plus regeneration commands ([`traces.sha256`](traces.sha256)).

- Every file under `data/derived/` can be rebuilt from the raw data with the commands in [docs/EXPERIMENTS.md](../docs/EXPERIMENTS.md#regenerating-the-derived-data). On 2026-10-02 the rebuild was byte-identical.
- `python3 -m analysis.headline` reads only files in git (this folder, [`w3/runs.tsv`](../w3/runs.tsv) and the patch) and writes [`artifacts/numbers.json`](../artifacts/numbers.json), the source of every number in the docs.
- Licenses: `derived/`, `verify/` and `ledger/` are CC BY 4.0 ([LICENSE-docs](../LICENSE-docs)). Model outputs inside the data were generated by Qwen/Qwen3-4B ([NOTICE](../NOTICE)).

## Era labels

Every run carries one of six era labels:

| Era | Meaning | Runs in `per_request.csv.gz` |
|---|---|---|
| `0903` | 2026-09-03 harness test, replayed before the server was up | 1 (all requests failed; excluded) |
| `0906` | 2026-09-06 unpatched baseline at 0.35 req/s (a re-run; see [incidents](#incidents)) | 1 |
| `0907` | 2026-09-07 unpatched exploration: two ablations at 0.35 req/s and the load sweep at 0.5–8 req/s | 9 |
| `0913` | 2026-09-13 runs of `w3/run_one.sh`, plus the failed re-run that overwrote the morning `--disable-radix-cache` result | 47 |
| `det` | 2026-09-13 deterministic-mode runs (`results/det/`, `logs/det/`) | 6 |
| `cross` | 2026-09-13 cross-workload replay (`results/cross/`) | 10 |

Two rule sets assign the labels, and they agree on every run in `per_request.csv.gz`:

- `per_request.csv.gz` assigns them by result name (`ERA_RULES` in [`w3/export_per_request.py`](../w3/export_per_request.py)).
- The release's `MANIFEST.tsv` uses the folder (`det/`, `cross/`) and otherwise the file's modification date in UTC as MMDD.

The manifest therefore labels two kinds of file differently from what their content suggests. The restored `results/backup/reasoning__noradix.orig.json` is `0913`: its file time is 09:58 on 09-13, when that run was recorded. `logs/server_cross_*.log` and `logs/cross_*_console.txt` are `0913`, because they are not in a `cross/` folder.

## Configuration names ("bars")

Result names are `<trace>__<bar>_r<N>.json`. The full list with server flags is in [docs/EXPERIMENTS.md](../docs/EXPERIMENTS.md#configurations-bars). The names that need care:

- **`default` depends on the era.** In the 09-13 data (`0913`, `cross`) it is the **patched build with the flag off**; in `det/` the same build is called `default_off`. In the 09-06 and 09-07 data (`reasoning__default`, `reasoning_q*__default`) it is **unpatched SGLang**. Flag off behaves like unpatched SGLang: deterministic outputs match <!--n:correct.det_q02up_vs_q02off-->120/120<!--/n-->, and at 2 req/s goodput is <!--n:q2.default.goodput_range-->0.4025–0.4035<!--/n--> vs <!--n:q2.upstream.goodput-->0.403<!--/n--> unpatched.
- `upstream` is unpatched SGLang on 09-13, run before the patch was applied.
- `mine_a<α>` is the patch with `--peak-kv-reserve-ratio α`; `mine` (in `cross/`) is α = 1.0. `mine_a1.0_p16` adds `--page-size 16`.
- `ablated` is `--chunked-prefill-size -1` (which also disables prefill CUDA graphs), `tuned_n<N>` is `--max-running-requests N`, `noradix` is `--disable-radix-cache`, and `cap65k` is `--max-total-tokens 65536`.
- `nograph` (09-07) turned CUDA graphs off; its exact flag was not logged. `batch_test` (09-03) is not a measurement.
- Trace names: `reasoning` = 0.35 req/s; `reasoning_qX` = X req/s; `_s0.3` and `_s1.0` = narrower or wider output-length spread; `_m1000` = mean output 1,000 tokens; `*_x` = the scaled-down cross-replay traces.

## Columns

Times are seconds and token counts are tokens unless a column says otherwise. Columns named `*_ms` or listed as ms are milliseconds. Percentiles are type 7 (linear interpolation), as in [`w3/metrics.py`](../w3/metrics.py).

### `w3_runs.csv`, `w3_det_runs.csv` (one row per run)

| Column | Unit | Meaning |
|---|---|---|
| `name`, `file`, `dataset`, `trace`, `tag` | – | Run name, result path, subfolder (`.` or `det`), trace stem, bar with repetition |
| `n_ok`, `n_err` | requests | Requests that finished / failed |
| `wall_s` | s | First submit to last completion, rounded to 0.1 s (goodput uses the unrounded span) |
| `ttft_p50`, `ttft_p99`, `ttft_mean` | ms | Time to first token |
| `wait10_reqs` | requests | Requests with TTFT > 10 s |
| `tpot_p50`, `tpot_p99` | ms | Per-request mean time per output token: (end − first token) / (tokens − 1) |
| `maxitl_p99` | ms | p99 over requests of each request's longest gap between streamed chunks ("p99 worst token gap") |
| `e2e_p50`, `e2e_p99` | ms | End-to-end latency |
| `out_tok_s` | tokens/s | Total output tokens / wall time |
| `cache_hit_%` | % | Cached prompt tokens / prompt tokens |
| `slo_%`, `goodput_rps` | %, req/s | Share and rate of requests meeting their SLO (mean TPOT ≤ 60 ms for these traces) |
| `aux_slo_%` | % | Requests that meet the SLO and have no gap > 5 s (the auxiliary SLO fixed in the plan) |
| `stall5_reqs`, `stall_max_s` | requests, s | Requests with a gap > 5 s; the longest gap |
| `retracted`, `retract_events` | requests, lines | Sum of `#retracted_reqs` over the server log's `Retract requests` lines; number of such lines |
| `max_usage` | 0–1 | Largest KV `token usage` in the server log |
| `max_running`, `max_queue`, `mean_running` | requests | Largest and mean `#running-req`, largest `#queue-req` |
| `graph_%` | % | Share of `Decode batch` log lines with `cuda graph: True` (one line per 40 decode steps, so a sample) |
| `peak_delays` | count | Last `#delays` value of the gate's log line. Logged at most every 5 s, so a lower bound; 0 when the gate is off |
| `recompute_tok` | tokens | From the `/metrics` dump: prefill tokens computed minus effective input tokens (KV recomputed after retractions) |
| `kv_pool` | tokens | `max_total_num_tokens` from the server log |
| `retracted_metric`, `retracted_out_tok` | requests, tokens | The `/metrics` retraction counters (retracted requests, their output tokens). Empty in runs without a retraction, because the counters appear only after their first increment; where present, `retracted_metric` equals `retracted` |

`ttft_mean` appears twice. The tables keep the as-run column layout, so they regenerate byte for byte.

### `w3_q2_grouped.csv`

One row per configuration at 2 req/s: `cond` (`<trace>__<bar>`) and `reps` (number of runs). Then, for each column of `w3_runs.csv`, the median and `<column>_min` / `<column>_max` over the runs. Units are as above. The median column of `graph_%` is always `nan`, a quirk of the as-run grouping code kept for byte-identical output; use `graph_%_min` / `graph_%_max`, or `w3_runs.csv`.

### `reasoning_q2_3bar_runs.csv`

`tag, n_ok, n_err, wall_s, ttft_p50, ttft_p99, tpot_p50, tpot_p99, maxitl_p99, e2e_p99, out_tok_s, cache_hit_%, slo_%, goodput_rps`, the standard summary of the course harness. Latencies are in ms, `wall_s` in s.

### `sweep_0907.csv` (09-07, unpatched, one row per load)

| Column | Unit | Meaning |
|---|---|---|
| `qps` | req/s | Arrival rate of the trace |
| `n_ok`, `wall_s`, `goodput_rps`, `slo_pct` | requests, s, req/s, % | As above |
| `ttft_p50_s`, `ttft_p99_s`, `maxitl_p99_s` | s | TTFT percentiles; p99 worst token gap |
| `tpot_p50_ms`, `tpot_p99_ms` | ms | TPOT percentiles (the submitted report printed p50 under the p99 heading; see ERRATA #1) |
| `retractions`, `max_token_usage` | requests, 0–1 | From the server log `logs/server_q<Q>.log` |
| `out_tok_s` | tokens/s | Total output / wall time |
| `wait10_reqs`, `stall5_reqs` | requests | TTFT > 10 s; gap > 5 s |
| `results_file`, `server_log` | – | Raw files used (in the release) |

### `per_request.csv.gz` (one row per request)

Gzip with a fixed header (mtime 0); rows are sorted by run, then request id. 25 columns:

| Column | Unit | Meaning |
|---|---|---|
| `run` | – | Result path under `results/` without `.json`, e.g. `reasoning_q2__default_r1`, `det/…`, `cross/…` |
| `era` | – | See [era labels](#era-labels) |
| `trace`, `bar`, `rep` | – | Trace stem; bar; repetition number (empty when the name has no `_rN`) |
| `rid`, `idx` | – | Request id; position in the result file |
| `submit_t`, `first_token_t`, `end_t` | s | Relative to the run's earliest submit |
| `ttft_s`, `e2e_s` | s | Empty for failed requests |
| `tpot_ms` | ms | Empty for failed requests and for requests with fewer than two tokens |
| `completion_tokens`, `prompt_tokens`, `cached_tokens` | tokens | As reported by the server |
| `max_gap_s`, `max_gap_start_s` | s | Longest gap between streamed chunks, and when it started (relative to the earliest submit) |
| `n_gaps_gt5s` | count | Gaps longer than 5 s |
| `slo_ok` | 1 / 0 | Empty for failed requests |
| `error` | – | Client error text, empty on success |
| `slo_class`, `ttft_slo_ms`, `tpot_slo_ms` | –, ms, ms | The request's SLO fields from the trace (empty = none) |
| `output_sha16` | – | First 16 hex digits of the SHA-256 of the generated text. Equal values mean identical outputs; the correctness numbers use them |

It covers the 74 result files in `results/`, `results/det/` and `results/cross/`. That includes the two runs in which every request failed (`reasoning__batch_test`, and the overwritten `reasoning__noradix`); they appear as 120 error rows each. It does not include `results/failed/` (the excluded q1 ablated run) or `results/backup/` (the restored original).

### `cum_output.csv.gz`

`run, pct, tokens, t_s`: the time `t_s` (relative to the earliest submit) at which output token number `tokens` = floor(total × pct / 100) arrived, for pct = 1…100. It shows when each share of the output was delivered; for example, half the output arrives later with the patch at 2 req/s.

### `server_logs.csv`

`log, retract_events, retracted_reqs, max_token_usage, max_running_reqs, max_queue_reqs, peak_kv_delays_logged, kv_pool_tokens`, one row per `logs/server_*.log` and `logs/det/server_*.log` (not `logs/failed/`). `peak_kv_delays_logged` is the last logged `#delays`, so it is a lower bound.

### `retract_cost/`

Output of `python3 -m analysis.retract_cost --sweep-0907` for the seven 09-07 sweep runs. Paths are repository-relative, and the CSV files start with a UTF-8 byte-order mark. `events.csv` has one row per retraction. The main columns are:

- `run`: the load;
- `log_time`, `retracted_reqs`: the server log line;
- `rid`: the victim request;
- `stall_start_s`, `stall_s`: the client-side stall;
- `retract_to_reprefill_s`: the delay from the retraction to the victim's re-prefill line, when found;
- `recompute_lb_event`, `recompute_ub_row`: bounds on the recomputed tokens;
- `victim_slo_ok`;
- `match_method`: whether time and token count match exactly or approximately; the labels are in Korean.

`summary.csv` has one row per load. `report.md` explains the method and links every number to a file line; it is in Korean. The module docstring of [`analysis/retract_cost.py`](../analysis/retract_cost.py) defines the terms.

## Incidents

- **Overwritten `--disable-radix-cache` run (0.35 req/s).** The original run was recorded on 09-13 at 09:58 on unpatched SGLang. A re-run at 12:22 started without a running server; all 120 requests failed, and it overwrote `results/reasoning__noradix.json`. The original was kept as a backup. The release ships it as `results/backup/reasoning__noradix.orig.json` (status `restored`), and the overwritten file is `excluded`. `per_request.csv.gz` contains the overwritten file as 120 error rows, not the original. None of the 09-13 conclusions use this run; the q2 `noradix` run is a separate, complete run.
- **Failed harness test (`batch_test`, 09-03).** The replay started before the server was ready, so all 120 requests failed to connect, and the server log shows no request. The run is not a measurement, although the submitted report's ablation screenshot showed it (ERRATA #5). It is `excluded` in the release and appears in `per_request.csv.gz` as 120 error rows.
- **Scheduler excerpts `logs/sched_*.txt` are not used.** They are the last 30 decode lines of the 09-07 sweep logs, taken during the drain phase, so they contain no retraction lines. `sched_default.txt` was overwritten with an excerpt of the 0.8 req/s log. They are not in git and no analysis reads them. The release keeps them unchanged (status `ok`) for completeness.
- **q1 ablated client error (09-13).** One request of `reasoning_q1__ablated_r1` failed with `ClientOSError: [Errno 104] Connection reset by peer` (status `ERR1` in `w3/runs.tsv`). The run was moved to `results/failed/` and `logs/failed/` (names end in `.err1`) and re-run at the end of the day; the re-run is the result used. See [docs/EXPERIMENTS.md](../docs/EXPERIMENTS.md#the-failed-run-and-its-re-run).
- **Lost 09-06 baseline.** The submitted report's baseline table (p. 3) came from a 09-06 run whose result file was overwritten by a re-run about an hour later (`results/reasoning__default.json`, era `0906`), and its server log was not kept. The reported values cannot be reproduced. The corrected baseline is the 09-13 unpatched median of three runs (`reasoning__upstream_r1`–`r3`; ERRATA #9).
- **Missing server logs for the 09-07 ablations.** `reasoning__ablated` and `reasoning__nograph` (0.35 req/s) have client results only, so their retraction counts and flags cannot be checked.
